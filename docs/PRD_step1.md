## 1. 배경과 목적

사용자는 냉장고에 무엇이 있는지는 알지만, 그 재료로 무엇을 만들지 떠올리기 어렵습니다. 1단계에서는 사용자가 냉장고 사진을 올리면 이미지 인식 모델이 식재료 목록을 뽑아 줍니다. 사용자는 그 목록을 직접 확인하고 고칩니다. 이렇게 확정한 목록이 2단계(레시피 생성)의 입력이 됩니다.

## 2. 목표와 비목표

**목표**
- 사진 한 장을 올리면 식재료 목록을 2분 안에 받아 볼 수 있다. 기본 모델이 붐벼도 예비 모델로 결과를 받는다.
- 사용자가 인식 결과를 추가, 수정, 삭제해서 "확정 재료 목록"을 만들 수 있다.
- 2·3단계에서도 그대로 쓸 수 있는 앱의 기본 골격(페이지 구조, 비밀 값 처리, OpenRouter 클라이언트)을 만든다.
- 비용 없이 Streamlit Community Cloud에 배포한다.

**비목표 (1단계에서 하지 않음)**
- 레시피 생성(2단계), 로그인과 저장(3단계)
- 유통기한 인식, 바코드 스캔, 영수증 인식
- 사진 여러 장을 한 번에 분석하기 (향후 검토)
- 업로드한 사진을 서버에 보관하기
- 브라우저를 새로고침해도 결과 유지하기. Streamlit 세션 상태는 새로고침하면 초기화되며, 1단계에서는 이를 감수한다.

## 3. 사용자 시나리오

1. 사용자가 앱 주소(`https://<앱이름>.streamlit.app`)를 연다.
2. "사진 올리기" 탭에서 냉장고 사진을 고르거나, "카메라로 찍기" 탭에서 바로 찍는다. 모바일에서는 사진 올리기를 누르면 휴대폰이 카메라와 갤러리 중 고르게 해 준다.
3. 사진 미리보기 아래의 "재료 인식" 버튼을 누른다.
4. 진행 상태 표시가 나온다. 무료 모델이라 요청이 몰리면 "요청이 몰려 10초 뒤 한 번 더 시도합니다", "기본 모델이 붐벼서 예비 모델(…)로 다시 시도합니다"처럼 진행 상황이 보인다.
5. 인식된 재료가 편집 가능한 표로 나온다. 표에는 재료명, 수량, 단위, 분류, 확인 필요 여부가 있다.
6. 사용자가 잘못 인식된 행은 지우고, 빠진 재료는 새 행으로 추가한 뒤 "이 재료로 레시피 찾기"를 누른다. 이 버튼은 2단계에서 연결된다.

## 4. 기능 요구사항

| ID | 요구사항 | 우선순위 |
|---|---|---|
| F1-1 | `st.file_uploader`로 JPEG, PNG, WEBP 이미지를 받는다. 최대 10MB(`max_upload_size=10`). | 필수 |
| F1-2 | `st.camera_input`으로 바로 찍을 수 있게 한다. 카메라 권한 요청이 매번 뜨지 않도록, "카메라로 찍기"를 고를 때만 카메라 위젯을 만든다. 입력 방법 전환은 `st.tabs` 대신 `st.segmented_control`을 쓴다(`st.tabs`는 모든 탭 내용을 한꺼번에 만들기 때문). 촬영 해상도는 `720p`로 요청한다. | 필수 |
| F1-3 | 고른 사진을 `st.image`로 미리 보여 준다. | 필수 |
| F1-4 | 올린 사진은 모델에 보내기 전에 자동으로 작게 변환한다. 긴 변 1024px, JPEG 품질 85에서 시작해 300KB 이하가 될 때까지 품질(85→75→65)을 낮추고, 그래도 크면 긴 변을 20%씩 줄인다(최소 640px). 이때 EXIF(위치 정보 포함)를 지우고, 그 전에 EXIF 회전 정보를 반영해서 사진이 눕지 않게 한다. 변환 결과(원본 용량·크기 → 변환 용량·크기)를 사진 아래에 보여 주고, 미리보기도 변환한 사진으로 보여 준다. | 필수 |
| F1-5 | 인식 결과는 재료명, 수량, 단위, 분류, 신뢰도로 구조화한다(6장 참고). | 필수 |
| F1-6 | 결과를 `st.data_editor`(`num_rows="dynamic"`)로 보여 줘서 행 추가, 수정, 삭제가 되게 한다. | 필수 |
| F1-7 | 신뢰도가 `low`인 재료는 "확인 필요" 열에 ⚠ 표시를 하고, 표 위에 "다음 재료는 사진에서 확실하지 않아요: …"라고 안내한다. | 필수 |
| F1-8 | 사진에서 식재료를 찾지 못했거나 냉장고 사진이 아니면, 그렇다고 알리고 다시 찍기를 권한다. | 필수 |
| F1-9 | 확정한 재료 목록은 `st.session_state`에 보관해서, 같은 세션에서 다른 페이지로 갔다가 돌아와도 유지되게 한다. | 필수 |
| F1-10 | 재료명은 한국어로, 같은 재료는 하나로 합쳐서 보여 준다(예: 달걀 여러 개 → "달걀 6개"). | 권장 |
| F1-11 | Streamlit은 위젯을 조작할 때마다 스크립트 전체를 다시 실행한다. 그러므로 모델 호출은 "재료 인식" 버튼을 눌렀을 때만 일어나야 한다. 결과는 `st.session_state`에 보관하고, 같은 이미지(바이트 해시)를 다시 인식할 때는 저장해 둔 결과를 쓴다. | 필수 |

## 5. 시스템 구성

```
브라우저
   │  (Streamlit이 웹소켓으로 화면과 위젯을 주고받음)
   ▼
Streamlit 앱 (Community Cloud 컨테이너)
   │  st.secrets["OPENROUTER_API_KEY"]
   │  Pillow로 이미지 전처리 → base64 data URL
   ▼
OpenRouter /api/v1/chat/completions
   └─ google/gemma-4-26b-a4b-it:free
```
- 화면과 서버 코드가 모두 Python 하나로 돌아가며, API 키는 서버 쪽에만 있다. 브라우저로는 화면만 전송되므로 키가 노출되지 않는다.

**기술 스택 (전 단계 공통)**
- 앱: Streamlit (문서 확인 기준 1.66). 여러 페이지는 `st.navigation`과 `st.Page`로 구성한다.
- OpenRouter 호출: `httpx`(동기). `scripts/test_openrouter.py`의 재시도 로직(429/502/503)을 옮겨 쓴다.
- 이미지 처리: Pillow
- 테스트: pytest. 화면 테스트는 Streamlit의 `AppTest`를 쓴다.
- 의존성: 저장소 루트의 `requirements.txt`. Community Cloud가 이 파일을 읽어 설치한다.

**폴더 구조**
```
streamlit_app.py         # 진입점: 페이지 등록(st.navigation), 공통 설정
app_pages/
  fridge.py              # 1단계 화면
core/
  config.py              # 비밀 값 로딩, 모델 ID, 제한 값
  openrouter.py          # OpenRouter 클라이언트 (재시도, 타임아웃, 오류 변환)
  vision.py              # 이미지 전처리, 프롬프트, 응답 파싱, 정규화
  usage.py               # 앱 전체 요청 횟수 제한
.streamlit/
  config.toml            # 업로드 크기, 테마 (커밋함)
  secrets.toml           # 로컬 비밀 값 (커밋 금지)
requirements.txt
tests/
```

**비밀 값 로딩 순서** (`core/config.py`)
1. `st.secrets["OPENROUTER_API_KEY"]`: Community Cloud에서는 앱 설정의 Secrets에, 로컬에서는 `.streamlit/secrets.toml`에 둔다.
2. 1이 없으면 환경 변수 `OPENROUTER_API_KEY`
3. 2도 없으면 프로젝트 루트의 `.env`. 기존 테스트 스크립트와 같은 파일을 쓸 수 있게 하기 위해서다.
4. 셋 다 없으면 앱 첫 화면에 "API 키가 설정되지 않았습니다"라고 보여 주고, 인식 버튼을 비활성화한다.
- `.gitignore`에 `.streamlit/secrets.toml`을 추가한다. 기존 pre-commit 훅은 `sk-or-v1-` 형식의 키가 들어 있으면 이 파일도 막는다.

## 6. 데이터 형식

화면과 로직 사이는 함수 호출로 연결된다. 별도의 HTTP API는 없다.

### `core.vision.recognize_ingredients(image_bytes, on_retry=None) -> RecognitionResult`

```json
{
  "ingredients": [
    { "name": "달걀", "quantity": 6, "unit": "개", "category": "유제품·달걀", "confidence": "high" },
    { "name": "대파", "quantity": 1, "unit": "단", "category": "채소", "confidence": "medium" },
    { "name": "김치", "quantity": null, "unit": null, "category": "반찬·가공식품", "confidence": "low" }
  ],
  "is_food_image": true,
  "notes": "아래 칸 일부가 가려져 있어 인식이 부정확할 수 있습니다.",
  "model": "google/gemma-4-26b-a4b-it:free",
  "elapsed_ms": 18234
}
```

- `category`는 다음 중 하나다: `채소`, `과일`, `육류`, `해산물`, `유제품·달걀`, `곡물·면`, `양념·소스`, `반찬·가공식품`, `음료`, `기타`
- `confidence`는 `high`, `medium`, `low` 중 하나다.
- `quantity`와 `unit`은 모델이 알 수 없으면 `null`이다.
- `on_retry(attempt, wait_seconds)`는 재시도할 때마다 불리는 콜백이다. 화면은 이것으로 진행 상태 문구를 바꾼다.

**오류**: 모든 오류는 `AppError(code, message)` 예외로 올라온다. 화면은 `message`를 `st.error`로 보여 준다.

| code | 상황 | 사용자 문구 예시 |
|---|---|---|
| `INVALID_IMAGE` | 이미지가 아니거나 열 수 없는 파일 | "이미지 파일을 열 수 없어요. JPEG, PNG, WEBP 사진을 올려 주세요." |
| `IMAGE_TOO_LARGE` | 10MB 초과 (위젯 제한을 우회한 경우를 대비해 서버에서도 확인) | "10MB 이하 사진만 올릴 수 있어요." |
| `PARSE_FAILED` | 재시도한 뒤에도 모델 응답을 JSON으로 해석하지 못함 | "인식 결과를 읽지 못했어요. 다시 시도해 주세요." |
| `MODEL_BUSY` | 기본 모델 재시도와 예비 모델이 모두 실패 | "무료 모델에 요청이 몰려 있어요. 1분쯤 뒤에 다시 시도해 주세요." |
| `DAILY_LIMIT` | 앱의 하루 요청 상한 도달 (9장 참고) | "오늘 준비된 무료 사용량을 모두 썼어요. 내일 다시 이용해 주세요." |
| `MODEL_TIMEOUT` | 모델 응답 시간 초과 | "응답이 너무 늦어요. 잠시 뒤 다시 시도해 주세요." |
| `UPSTREAM_ERROR` | 그 밖의 OpenRouter 오류 | "인식 서비스에 문제가 생겼어요." |
| `CONFIG_ERROR` | API 키 없음 | "API 키가 설정되지 않았습니다." |

## 7. 모델 연동 설계

**요청 형식** (`scripts/test_openrouter.py`에서 검증한 방식)
```json
{
  "model": "google/gemma-4-26b-a4b-it:free",
  "messages": [
    { "role": "system", "content": "<시스템 프롬프트>" },
    { "role": "user", "content": [
      { "type": "text", "text": "이 냉장고 사진의 식재료를 JSON으로 알려 줘." },
      { "type": "image_url", "image_url": { "url": "data:image/jpeg;base64,..." } }
    ]}
  ],
  "response_format": { "type": "json_object" },
  "temperature": 0.2,
  "max_tokens": 2048
}
```
- 이 모델은 `response_format`은 지원하지만 `structured_outputs`(JSON 스키마 강제)는 지원하지 않는다. 그래서 서버에서 스키마 검증을 직접 해야 한다.

**시스템 프롬프트 요지**
- 너는 냉장고 사진에서 식재료를 찾는 도우미다.
- 실제로 보이는 식재료만 나열하고, 추측한 재료는 `confidence: "low"`로 표시한다.
- 불투명한 용기나 포장처럼 내용물을 알 수 없는 것은 목록에서 빼고, `notes`에 언급한다.
- 재료명은 한국어 일반 명칭으로 쓴다(상표명 대신 "우유", "케첩").
- 지정한 JSON 스키마만 출력하고, 다른 텍스트는 쓰지 않는다.

**응답 처리**
1. `choices[0].message.content`에서 JSON을 꺼낸다. 코드 블록(```json)으로 감싸 오면 벗겨 내고, 그래도 안 되면 첫 `{`부터 마지막 `}`까지를 잘라 다시 시도한다.
2. 스키마를 검증한다. 필수 필드가 빠지면 1회 다시 요청하고, 그래도 실패하면 `PARSE_FAILED`를 낸다.
3. 정규화한다: 재료명 앞뒤 공백 제거, 같은 이름은 합치기, 허용되지 않은 `category`는 `기타`로 바꾸기, 숫자가 아닌 `quantity`(예: "약간")는 `null`로 바꾸기.

**재시도, 예비 모델 전환, 타임아웃**
- 기본 모델이 429, 502, 503을 돌려주면 10초 기다렸다가 같은 모델로 **한 번 더** 시도한다.
- 그래도 실패하면(일시적 오류나 시간 초과) **예비 무료 비전 모델**로 차례로 넘어간다. 예비 모델은 기다리지 않고 한 번씩만 시도하며, 어떤 오류든 다음 모델로 넘어간다. API 키 오류(401)는 예비 모델로 넘어가도 소용없으므로 바로 끝낸다.
- 예비 모델 목록(`FALLBACK_VISION_MODELS`, 덜 붐빌 모델을 앞에 둠). OpenRouter API는 모델별 인기(사용량)를 제공하지 않으므로, 2026-10-18 실제 호출로 확인해서 골랐다.

  | 순서 | 모델 | 고른 이유 |
  |---|---|---|
  | 1 | `dots-studio/dots-3-note-preview:free` | 덜 알려진 프리뷰 모델. 이미지 인식과 JSON 형식 지정 모두 동작 확인 |
  | 2 | `nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free` | 추론 모델. 확인 시점에는 NVIDIA 쪽 처리량이 차 있었지만 목록에 유지 |
  | 3 | `nvidia/nemotron-3.5-super-vl:free` | 동작 확인. 사용량이 매우 많은 인기 모델이라 마지막에 둠 |

  - 제외: `google/gemma-4-31b-it:free`(기본 모델과 같은 Google 공유 한도를 써서 함께 막힘), `thinkingmachines/inkling*:free`(에이전트 도구 전용, 403), `nvidia/nemotron-3.5-content-safety:free`(안전성 분류 전용)
- 앱은 OpenRouter 모델 목록(`/api/v1/models`, 6시간 캐시)을 읽어서, 지금 무료로 이미지를 받는 모델만 예비로 쓴다. 목록에서 사라진 모델은 자동으로 건너뛴다. `response_format`은 지원하는 모델에만 보낸다(목록을 못 읽으면 기본 모델에만).
- 응답을 해석하지 못해 다시 요청할 때는, 기본 모델부터 다시 시작하지 않고 방금 응답한 모델에 보낸다.
- 전체 처리 시간은 120초, 요청 하나는 60초로 제한한다. 남은 시간이 다음 대기 시간보다 짧으면 기다리지 않는다.
- 예비 모델로 인식했으면 결과 위에 "기본 모델이 붐벼서 예비 모델(…)로 인식했어요"라고 알린다.
- 화면은 `st.status`로 "사진 준비 중 → 재료 인식 중 → (재시도 안내) → 완료" 순서로 진행 상황을 보여 준다.

## 8. 화면 요구사항

- **페이지 제목**: "냉장고 재료 찾기". 사이드바에 단계별 페이지 메뉴를 둔다(2·3단계 페이지는 구현되기 전까지 숨긴다).
- **입력 영역**: `st.tabs(["사진 올리기", "카메라로 찍기"])`.
- **미리보기**: 사진 아래에 "재료 인식" 버튼(`type="primary"`). 인식 중에는 버튼을 비활성화해서 중복 요청을 막는다.
- **결과 표** (`st.data_editor`)

| 열 | 형식 | 비고 |
|---|---|---|
| 재료명 | 텍스트 (필수) | |
| 수량 | 숫자 (0 이상) | 비울 수 있음 |
| 단위 | 텍스트 | 비울 수 있음 |
| 분류 | 선택 상자 | 6장의 분류 목록 |
| 확인 필요 | 읽기 전용 | `low`이면 ⚠ |

- **메모**: 모델의 `notes`가 있으면 `st.info`로 보여 준다.
- **다음 단계 버튼**: "이 재료로 레시피 찾기". 재료명이 있는 행이 1개 이상일 때만 활성화된다. 2단계가 구현되기 전에는 누르면 "다음 단계에서 연결됩니다"라는 안내만 보여 준다.
- **사용량 안내**: 사이드바 아래에 "무료 모델을 쓰고 있어 응답이 늦거나 하루 사용량이 제한될 수 있어요"라고 표시한다.
- 모바일 화면(너비 360px)에서도 표와 버튼이 잘리지 않아야 한다. 표는 화면 너비에 맞춘다(`width="stretch"`).

## 9. 비기능 요구사항

| 구분 | 요구사항 |
|---|---|
| 성능 | 모델 응답을 제외한 처리(전처리, 파싱)는 1초 이내. 정상일 때 전체 응답 시간 목표는 40초 이내(테스트 기준 약 39초). |
| 보안 | API 키는 `st.secrets`나 서버 환경 변수로만 읽고, 화면, 로그, 오류 메시지에 남기지 않는다. OpenRouter 오류 원문을 화면에 그대로 보여 주지 않는다. |
| 개인정보 | 업로드한 이미지는 메모리에서만 처리하고, 디스크나 로그에 저장하지 않는다. EXIF를 지운다. 앱은 미국 서버에서 돌아간다(Community Cloud 정책). |

| 로깅 | 소요 시간, 모델, HTTP 상태, 재시도 횟수만 표준 출력으로 기록한다. 이미지와 프롬프트 본문은 기록하지 않는다. |

## 10. 배포 (Streamlit Community Cloud)

1. 저장소 `logistex/recipe4fridge-demo`의 `main` 브랜치에 `streamlit_app.py`와 `requirements.txt`를 푸시한다.
2. https://share.streamlit.io 에 GitHub 계정으로 로그인하고 "Create app"을 누른다.
3. 저장소, 브랜치(`main`), 진입점(`streamlit_app.py`)을 고르고, 원하는 앱 주소(서브도메인)를 정한다.
4. "Advanced settings"에서 다음을 설정한다.
   - Python 버전: 로컬 개발 버전과 같게 맞춘다(Community Cloud 기본값은 3.12, 로컬은 3.14).
   - Secrets: `OPENROUTER_API_KEY = "..."` 를 붙여 넣는다.
5. 배포한 뒤 `main`에 푸시하면 앱이 자동으로 다시 배포된다.

**Community Cloud의 제약** (2026-10 확인)
- 12시간 동안 접속이 없으면 앱이 잠들고, 다음 방문자가 깨워야 한다.
- 실행 중에 만든 파일은 재시작하거나 재배포하면 사라진다. 1단계는 파일을 저장하지 않으므로 문제없다.
- 자원 한도: CPU 최대 2코어, 메모리 최대 약 2.7GB.
- `config.toml`에서 바꿔도 `showErrorDetails = false`, `enableXsrfProtection = true`가 강제된다.

## 12. 위험 요소와 대응

| 위험 | 대응 |
|---|---|
| 무료 모델의 429와 하루 50회 한도 | 재시도 1회 후 예비 모델 전환, 진행 상태 안내, 세션별·앱 전체 요청 제한. 하루 상한은 인식 1번을 1회로 세지만, 재시도와 예비 모델 전환으로 실제 OpenRouter 요청은 최대 6회(기본 2 + 예비 3 + 해석 실패 재요청 1)까지 늘 수 있다(429 응답이 OpenRouter 하루 한도에 포함되는지는 공개되어 있지 않음). 필요하면 크레딧 10 이상 구매(하루 1,000회)나 유료 모델로 바꿀 수 있도록 모델 ID를 설정으로 분리한다. |
| 공개 앱이라 다른 사람이 한도를 다 써 버림 | 앱 전체 하루 상한. 3단계 이후에는 로그인한 사용자만 인식을 쓰게 바꾸는 방안을 검토한다. |
| Streamlit 재실행 때문에 모델이 반복 호출됨 | 버튼을 눌렀을 때만 호출하고, 결과와 이미지 해시를 세션 상태에 보관한다(F1-11). |
| `st.camera_input`이 모바일에서 전면 카메라로 열릴 수 있음 | 공식 문서에 후면 카메라 지정 방법이 없다. "사진 올리기"(휴대폰 기본 카메라 앱 사용)를 첫 번째 탭으로 두고 권장한다. |
| 반찬통, 검은 봉지처럼 내용물이 보이지 않는 재료 | 신뢰도 표시와 사용자 직접 수정 흐름으로 보완한다. |
| 모델이 JSON 형식을 어김 | `response_format`, 파싱 보정, 1회 재요청을 차례로 적용한다. |
| 무료 모델이 사라지거나 바뀜 | 모델 ID와 예비 모델 목록을 `st.secrets`나 환경 변수로 바꿀 수 있게 하고, 예비 모델은 실시간 모델 목록으로 걸러 낸다. |
