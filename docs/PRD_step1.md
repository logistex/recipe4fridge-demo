# PRD 1단계: 냉장고 사진 식재료 인식

| 항목 | 내용 |
|---|---|
| 제품 | 냉장고 사진 기반 레시피 추천 웹 애플리케이션 |
| 단계 | 1 / 3 (식재료 인식) |
| 사용 모델 | `google/gemma-4-26b-a4b-it:free` (OpenRouter) |
| 다음 단계 | [PRD_step2.md](PRD_step2.md): 인식 결과로 레시피 생성 |
| 작성일 | 2026-10-18 |

## 1. 배경과 목적

사용자는 냉장고에 무엇이 있는지는 알지만, 그 재료로 무엇을 만들지 떠올리기 어렵습니다. 1단계에서는 사용자가 냉장고 사진을 올리면 이미지 인식 모델이 식재료 목록을 뽑아 줍니다. 사용자는 그 목록을 직접 확인하고 고칩니다. 이렇게 확정한 목록이 2단계(레시피 생성)의 입력이 됩니다.

## 2. 목표와 비목표

**목표**
- 사진 한 장을 올리면 식재료 목록을 1분 안에 받아 볼 수 있다.
- 사용자가 인식 결과를 추가, 수정, 삭제해서 "확정 재료 목록"을 만들 수 있다.
- 2단계 이후에도 그대로 쓸 수 있는 웹 앱의 기본 골격(서버, 화면, API 키 처리)을 만든다.

**비목표 (1단계에서 하지 않음)**
- 레시피 생성(2단계), 로그인과 저장(3단계)
- 유통기한 인식, 바코드 스캔, 영수증 인식
- 사진 여러 장을 한 번에 분석하기 (향후 검토)
- 업로드한 사진을 서버에 보관하기

## 3. 사용자 시나리오

1. 사용자가 웹 페이지를 열고 "냉장고 사진 올리기"를 누른다. 모바일에서는 카메라가 바로 열린다.
2. 사진을 고르면 미리보기가 나오고, "재료 인식" 버튼을 누른다.
3. 분석이 진행되는 동안 로딩 표시가 나온다. 무료 모델이라 대기 중이면 "요청이 몰려 재시도 중"이라는 안내가 나온다.
4. 인식된 재료가 카드 목록으로 나온다. 카드마다 재료명, 대략적인 수량, 신뢰도가 표시된다.
5. 사용자가 잘못 인식된 재료는 지우고, 빠진 재료는 직접 추가한 뒤 "이 재료로 레시피 찾기"를 누른다. 이 버튼은 2단계에서 연결된다.

## 4. 기능 요구사항

| ID | 요구사항 | 우선순위 |
|---|---|---|
| F1-1 | JPEG, PNG, WEBP 이미지를 업로드할 수 있다. 원본은 최대 10MB까지 받는다. | 필수 |
| F1-2 | 모바일에서는 `<input type="file" accept="image/*" capture="environment">`로 후면 카메라를 바로 연다. | 필수 |
| F1-3 | 업로드 전에 사진 미리보기를 보여 준다. | 필수 |
| F1-4 | 서버는 이미지의 긴 변을 1280px 이하로 줄이고 JPEG(품질 85)로 다시 인코딩한 뒤 모델에 보낸다. 이때 EXIF(위치 정보 포함)를 지운다. | 필수 |
| F1-5 | 인식 결과는 재료명, 수량, 단위, 분류, 신뢰도로 구조화한다(6장 참고). | 필수 |
| F1-6 | 사용자는 결과 목록에서 재료를 추가, 수정, 삭제할 수 있다. | 필수 |
| F1-7 | 신뢰도가 `low`인 재료는 시각적으로 구분하고, 확인을 유도하는 문구를 보여 준다. | 필수 |
| F1-8 | 사진에서 식재료를 찾지 못했거나 냉장고 사진이 아니면, 그렇다고 알리고 다시 찍기를 권한다. | 필수 |
| F1-9 | 확정한 재료 목록은 브라우저 `sessionStorage`에 보관해서, 새로고침해도 유지되게 한다. | 권장 |
| F1-10 | 재료명은 한국어로, 같은 재료는 하나로 합쳐서 보여 준다(예: 달걀 여러 개 → "달걀 6개"). | 권장 |

## 5. 시스템 구성

```
브라우저 (HTML + JS)
   │  multipart/form-data (이미지)
   ▼
웹 서버 (FastAPI)  ── .env의 OPENROUTER_API_KEY 사용
   │  이미지 전처리 (Pillow) → base64 data URL
   ▼
OpenRouter /api/v1/chat/completions
   └─ google/gemma-4-26b-a4b-it:free
```

**기술 스택 (전 단계 공통)**
- 백엔드: Python, FastAPI, uvicorn. 둘 다 아직 설치되어 있지 않으므로 `requirements.txt`를 새로 만든다.
- OpenRouter 호출: `httpx`(비동기)를 쓰거나, `scripts/test_openrouter.py`의 `chat()` 로직(429/502/503 재시도)을 옮겨 쓴다.
- 이미지 처리: Pillow (이미 설치되어 있음)
- 프론트엔드: 빌드 도구가 필요 없는 정적 HTML, CSS, JS. FastAPI가 `static/`으로 서빙한다.
- 설정: `.env`를 서버에서만 읽는다. API 키는 브라우저로 절대 보내지 않는다.

**권장 폴더 구조**
```
app/
  main.py            # FastAPI 앱, 라우터 등록, 정적 파일 서빙
  config.py          # .env 로딩, 모델 ID 상수
  openrouter.py      # OpenRouter 클라이언트 (재시도, 타임아웃, 오류 변환)
  routers/ingredients.py
  services/vision.py # 프롬프트, 응답 파싱, 정규화
static/
  index.html, app.js, style.css
requirements.txt
```

## 6. API 명세

### `POST /api/ingredients/recognize`

**요청**: `multipart/form-data`
- `image` (파일, 필수)

**응답 200**
```json
{
  "ingredients": [
    { "name": "달걀", "quantity": 6, "unit": "개", "category": "유제품·달걀", "confidence": "high" },
    { "name": "대파", "quantity": 1, "unit": "단", "category": "채소", "confidence": "medium" },
    { "name": "김치", "quantity": null, "unit": null, "category": "반찬·가공식품", "confidence": "low" }
  ],
  "is_food_image": true,
  "notes": "아래 칸 일부가 가려져 있어 인식이 부정확할 수 있습니다.",
  "model": "google/gemma-4-26b-a4b-it:free",
  "elapsed_ms": 18234
}
```

- `category`는 다음 중 하나다: `채소`, `과일`, `육류`, `해산물`, `유제품·달걀`, `곡물·면`, `양념·소스`, `반찬·가공식품`, `음료`, `기타`
- `confidence`는 `high`, `medium`, `low` 중 하나다.
- `quantity`와 `unit`은 모델이 알 수 없으면 `null`이다.

**오류 응답** (모두 `{ "error": { "code": "...", "message": "사용자에게 보여 줄 한국어 문구" } }` 형식)

| HTTP | code | 상황 |
|---|---|---|
| 400 | `INVALID_IMAGE` | 이미지가 아니거나 열 수 없는 파일 |
| 413 | `IMAGE_TOO_LARGE` | 10MB 초과 |
| 422 | `PARSE_FAILED` | 재시도한 뒤에도 모델 응답을 JSON으로 해석하지 못함 |
| 503 | `MODEL_BUSY` | OpenRouter 429가 계속됨 (재시도 소진) |
| 504 | `MODEL_TIMEOUT` | 모델 응답 시간 초과 |
| 502 | `UPSTREAM_ERROR` | 그 밖의 OpenRouter 오류 |

## 7. 모델 연동 설계

**요청 형식** (앞서 `scripts/test_openrouter.py`에서 검증한 방식)
```json
{
  "model": "google/gemma-4-26b-a4b-it:free",
  "messages": [
    { "role": "system", "content": "<시스템 프롬프트>" },
    { "role": "user", "content": [
      { "type": "text", "text": "이 냉장고 사진의 식재료를 JSON으로 알려 줘." },
      { "type": "image_url", "image_url": { "url": "data:image/jpeg;base64,..." } }
    ]}
  ],
  "response_format": { "type": "json_object" },
  "temperature": 0.2,
  "max_tokens": 2048
}
```
- 이 모델은 `response_format`은 지원하지만 `structured_outputs`(JSON 스키마 강제)는 지원하지 않는다. 그래서 서버에서 스키마 검증을 직접 해야 한다.

**시스템 프롬프트 요지**
- 너는 냉장고 사진에서 식재료를 찾는 도우미다.
- 실제로 보이는 식재료만 나열하고, 추측한 재료는 `confidence: "low"`로 표시한다.
- 용기나 포장만 보이고 내용물을 알 수 없으면 "알 수 없는 반찬통"처럼 적지 말고 빼되, `notes`에 언급한다.
- 재료명은 한국어 일반 명칭으로 쓴다(상표명 대신 "우유", "케첩").
- 지정한 JSON 스키마만 출력하고, 다른 텍스트는 쓰지 않는다.

**응답 처리**
1. `choices[0].message.content`에서 JSON을 꺼낸다. 코드 블록(```json)으로 감싸 오면 벗겨 내고, 그래도 안 되면 첫 `{`부터 마지막 `}`까지를 잘라 다시 시도한다.
2. 스키마를 검증한다(pydantic). 필수 필드가 빠지면 1회 다시 요청하고, 그래도 실패하면 `PARSE_FAILED`를 돌려준다.
3. 정규화한다: 재료명 앞뒤 공백 제거, 같은 이름은 합치기, 허용되지 않은 `category`는 `기타`로 바꾸기.

**재시도와 타임아웃**
- 429, 502, 503 응답이 오면 10초, 20초 간격으로 최대 2회 재시도한다. 실제 테스트에서도 Gemma 무료 모델은 공유 요청 한도 때문에 429가 자주 났다.
- 요청 하나의 타임아웃은 180초다. 재시도를 포함한 전체 처리 시간이 90초를 넘으면 `MODEL_BUSY`로 끝내고, 사용자에게 잠시 뒤 다시 시도하라고 안내한다.
- 재시도하는 동안 화면에 진행 상태를 보여 준다. 1단계에서는 고정 문구로 충분하고, SSE를 이용한 진행 상황 전송은 향후 개선 과제다.

## 8. 화면 요구사항

- **업로드 영역**: 드래그 앤 드롭과 파일 선택을 모두 지원한다. 모바일에서는 카메라를 바로 연다.
- **미리보기**: 선택한 사진을 썸네일로 보여 주고, "다시 선택"과 "재료 인식" 버튼을 둔다.
- **로딩 상태**: 스피너와 함께 "재료를 찾고 있어요(최대 1분 정도 걸릴 수 있어요)"라고 표시한다. 인식 중에는 버튼을 비활성화해서 중복 요청을 막는다.
- **결과 목록**: 분류별로 묶은 재료 카드를 보여 준다. 카드에는 재료명, 수량, 단위 편집 칸과 삭제 버튼이 있다. 신뢰도 `low`인 카드는 점선 테두리와 "확인 필요" 배지로 구분한다.
- **재료 직접 추가**: 이름(필수), 수량, 단위를 입력하는 줄을 둔다.
- **다음 단계 버튼**: "이 재료로 레시피 찾기". 확정한 재료가 1개 이상일 때만 활성화된다.
- 모바일(너비 360px)부터 데스크톱까지 반응형으로 동작한다.

## 9. 비기능 요구사항

| 구분 | 요구사항 |
|---|---|
| 성능 | 모델 응답을 제외한 서버 처리(전처리, 파싱)는 1초 이내. 정상일 때 전체 응답 시간 목표는 40초 이내(테스트 기준 약 39초). |
| 보안 | API 키는 서버 환경 변수로만 쓰고 로그나 응답에 남기지 않는다. 오류 메시지에 OpenRouter 원문을 그대로 노출하지 않는다. |
| 개인정보 | 업로드한 이미지는 메모리에서만 처리하고 디스크나 로그에 저장하지 않는다. EXIF를 지운다. |
| 사용량 | 무료 모델 요청 한도가 있으므로 서버에 IP당 분당 5회 업로드 제한을 둔다. |
| 로깅 | 요청 ID, 소요 시간, 모델, HTTP 상태, 재시도 횟수만 기록한다. 이미지와 프롬프트 본문은 기록하지 않는다. |

## 10. 수용 기준

- [ ] `scripts/test_image.png`(빨간 원, 파란 사각형, 초록 삼각형)처럼 식재료가 없는 이미지를 올리면 `is_food_image: false`나 빈 목록이 나오고, 다시 찍으라는 안내가 보인다.
- [ ] 재료를 미리 알고 있는 실제 냉장고 사진 3장 이상으로 테스트했을 때, 눈에 잘 보이는 재료의 80% 이상을 인식한다(사람이 표시한 정답과 비교).
- [ ] 모델이 코드 블록이나 설명 문장을 섞어 응답해도 결과가 정상적으로 파싱된다(단위 테스트로 확인).
- [ ] OpenRouter가 429를 돌려주는 상황을 흉내 내면 재시도 후 `MODEL_BUSY` 안내가 나오고, 화면이 멈추지 않는다.
- [ ] 10MB가 넘는 파일이나 이미지가 아닌 파일은 모델을 호출하기 전에 거부된다.
- [ ] 브라우저 개발자 도구의 네트워크 탭과 페이지 소스 어디에도 API 키가 보이지 않는다.
- [ ] 결과 목록을 수정한 뒤 새로고침해도 수정한 내용이 유지된다.

## 11. 위험 요소와 대응

| 위험 | 대응 |
|---|---|
| 무료 모델의 429와 일일 사용 한도 | 재시도, 사용자 안내, IP별 업로드 제한. 필요하면 유료 모델로 바꿀 수 있도록 모델 ID를 설정으로 분리한다. |
| 반찬통, 검은 봉지처럼 내용물이 보이지 않는 재료 | 신뢰도 표시와 사용자 직접 수정 흐름으로 보완한다. |
| 모델이 JSON 형식을 어김 | `response_format`, 파싱 보정, 1회 재요청을 차례로 적용한다. |
| 무료 모델이 사라지거나 바뀜 | 모델 ID는 `config.py`나 `.env`에서 바꿀 수 있게 한다. |

## 12. 2단계로 넘기는 데이터

```json
{ "ingredients": [ { "name": "달걀", "quantity": 6, "unit": "개", "category": "유제품·달걀" } ] }
```

## 13. 미결정 사항

- 사진 여러 장(냉장실과 냉동실)을 한 번에 분석할지 여부
- 인식 결과를 화면에 하나씩 흘려보내는 스트리밍 표시를 할지 여부
